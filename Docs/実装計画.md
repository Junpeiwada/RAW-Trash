# RAW-Trash 実装計画

## 概要

仕様書に基づき、Electron + TypeScript + React + Webpack 構成で RAW-Trash を実装する。

---

## 使用ツール・方針

| 項目 | 採用内容 | 理由 |
|------|---------|------|
| プロジェクト初期化 | **electron-forge** | Electron 公式推奨 CLI。Webpack + TypeScript テンプレートで一括セットアップ可能 |
| バンドラ | Webpack（forge 組み込み） | テンプレートに含まれており追加設定不要 |
| UI フレームワーク | React + TypeScript | 仕様書指定。forge 初期化後に手動追加 |
| IPC 通信 | contextBridge + ipcMain/ipcRenderer | Electron 推奨のセキュアな通信パターン |

## セットアップ手順

### Step 1: プロジェクト初期化

```bash

cd /Users/junpeiwada/Documents/Project/RAW-Trash

npx create-electron-app@latest . --template=webpack-typescript
```


**tsconfig.json の更新:**
```json

  }

```

**webpack.renderer.config.ts の更新:**  
`.tsx` 拡張子の解決を追加する。

### Step 3: 開発・ビルドコマンド確認

```bash
npm start        # 開発モード起動（HMR 付き）
npm run make     # macOS 向けパッケージ作成
```

```typescript
import { contextBridge, ipcRenderer } from 'electron';

contextBridge.exposeInMainWorld('electronAPI', {
  executeSort: (folderPath: string) =>
    ipcRenderer.invoke('sort:execute', folderPath),
  openFolderDialog: () =>
    ipcRenderer.invoke('dialog:openFolder'),
});
```

- [ ] `src/preload/preload.ts` を実装
- [ ] `window.electronAPI` の型定義を `src/renderer/global.d.ts` に追加

#### main.ts の IPC ハンドラ

| ハンドラ | 処理内容 |
|---------|---------|
| `dialog:openFolder` | `dialog.showOpenDialog` でフォルダ選択ダイアログを開き、パスを返す |
| `sort:execute` | 受け取ったパスに対してファイル整理処理を実行し、`SortResult` を返す |

- [ ] `ipcMain.handle('dialog:openFolder', ...)` を実装

### Phase 4: ファイル整理ロジック（main プロセス）

`sort:execute` ハンドラ内部の処理:

1. **サブフォルダ作成**: `Del/`, `RAW/`, `JPG/` を `fs.mkdirSync` で作成（`{ recursive: true }`）
2. **RAW ファイルスキャン**: `fs.readdirSync` で直下のファイルを列挙し、対象 RAW 拡張子を抽出
3. **孤立 RAW 検出**: 同名 JPG（大文字小文字不問）が存在しない RAW を `Del/` へ移動
4. **ファイル分類**: 残った RAW → `RAW/`、JPG → `JPG/` へ移動
5. **件数集計**: `SortResult` を構築して返却

```typescript
const RAW_EXTENSIONS = ['.arw', '.orf', '.cr3', '.cr2'];

function isRaw(ext: string): boolean {
  return RAW_EXTENSIONS.includes(ext.toLowerCase());
}

function isJpg(ext: string): boolean {
  return ['.jpg', '.jpeg'].includes(ext.toLowerCase());
}
```

- [ ] ファイル整理ロジックを実装（`src/main/sorter.ts` として分離推奨）
- [ ] エラーハンドリング（フォルダ不存在・移動失敗）を実装

## IPC フロー図

```
Renderer (React)
  │
  │  window.electronAPI.openFolderDialog()
  │  window.electronAPI.executeSort(path)
  ▼
Preload (contextBridge)
  │
  │  ipcRenderer.invoke('dialog:openFolder')
  │  ipcRenderer.invoke('sort:execute', path)
  ▼
Main Process
  │
  ├── dialog.showOpenDialog → パスを返す
  └── sortFiles(path) → SortResult を返す
```

## セキュリティ設定

- `contextIsolation: true`（デフォルト）
- `nodeIntegration: false`（デフォルト）
- preload 経由の最小限 API のみ公開
- macOS 配布時: entitlements.plist に `allow-jit` / `allow-unsigned-executable-memory` を設定

---

## 備考

- `webUtils.getPathForFile` は Electron 32 以降でレンダラーから直接呼び出し可能だが、preload 経由が推奨
- ファイル移動は `fs.renameSync`（同一ボリューム前提）を使用。クロスボリュームの場合は `fs.copyFileSync` + `fs.unlinkSync` にフォールバックが必要
- 対象ファイルは対象フォルダの**直下のみ**（サブフォルダ内は対象外）
